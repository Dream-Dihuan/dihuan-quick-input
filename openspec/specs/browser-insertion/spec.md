# browser-insertion Specification

## Purpose

通过配套浏览器扩展把桌面应用解析出的文本可靠写入当前网页聚焦的表单控件，并管理本地连接、焦点跟踪、失败反馈和隐私边界。

## Requirements

### Requirement: 扩展配对与鉴权
桌面应用 SHALL 生成并持久化一个配对令牌，扩展 MUST 在连接时提供该令牌；令牌缺失或不匹配的连接 MUST 被拒绝。用户 SHALL 能在设置页查看和轮换令牌，轮换后已连接扩展 MUST 被断开并需要重新配对。

#### Scenario: 使用正确令牌连接

- **WHEN** 扩展配置了与桌面应用一致的配对令牌并建立连接
- **THEN** 桌面设置页显示扩展已连接，扩展可以接收插入请求

#### Scenario: 令牌错误被拒绝

- **WHEN** 扩展使用错误的配对令牌发起连接
- **THEN** 桌面应用拒绝连接，设置页不显示为已连接

#### Scenario: 轮换令牌

- **WHEN** 用户在设置页轮换配对令牌
- **THEN** 现有扩展连接被断开，旧令牌不再被接受

### Requirement: 仅本地连接与自动重连
桌面应用 MUST 只在回环地址上监听本地连接，不得向外部网络暴露服务。扩展在浏览器启动、桌面应用重启或连接中断后 SHALL 自动尝试重连，无需用户手动刷新页面；连接状态变化 MUST 反映在设置页。

#### Scenario: 先启动浏览器后启动桌面应用

- **WHEN** 浏览器扩展已加载，随后桌面应用启动
- **THEN** 扩展自动连接，设置页在无需手动操作的情况下显示已连接

#### Scenario: 桌面应用重启

- **WHEN** 桌面应用重启导致连接中断
- **THEN** 扩展自动重连，后续插入请求继续可用

#### Scenario: 外部设备无法访问

- **WHEN** 另一台设备尝试连接桌面应用的本地服务
- **THEN** 连接无法建立

### Requirement: 焦点字段跟踪
扩展 SHALL 跟踪当前活动标签页中最后获得焦点的可编辑字段，并记录其所在 iframe。支持的单行输入类型至少包括 `text`、`search`、`email`、`url`、`tel`，同时支持 `textarea` 和 `contenteditable` 元素；禁用、只读、隐藏、不可见、文件、密码及非文本控件 MUST 被排除。页面导航或字段从文档移除后，对应记录 MUST 失效。

#### Scenario: 记录当前字段

- **WHEN** 用户在网页的文本输入框中点击并获得焦点
- **THEN** 扩展记录该字段作为下一次插入目标

#### Scenario: 切换标签页

- **WHEN** 用户在一个标签页聚焦字段后切换到另一个标签页
- **THEN** 插入请求只作用于新活动标签页中记录的字段；新标签页没有记录时不得写入旧标签页

#### Scenario: 页面导航后记录失效

- **WHEN** 用户聚焦字段后页面发生导航
- **THEN** 旧字段记录失效，插入请求返回无可用字段错误

#### Scenario: 密码框被排除

- **WHEN** 用户聚焦密码输入框后提交命令
- **THEN** 扩展不把密码框作为插入目标并返回无可用字段错误

### Requirement: 多浏览器连接目标选择
当 Chrome、Edge 或多个浏览器实例同时连接时，桌面应用 MUST 只向最近处于前台并报告过页面焦点的那个连接发送插入请求，不得向所有连接广播。无法确定最近活动连接时，系统 MUST 返回明确错误，不得猜测目标。

#### Scenario: 两个浏览器同时连接

- **WHEN** Chrome 与 Edge 都连接桌面应用，用户最近在 Chrome 的表单中聚焦字段后按下快捷键
- **THEN** 只有 Chrome 中的字段被写入，Edge 页面保持不变

#### Scenario: 无法确定活动浏览器

- **WHEN** 多个连接存在但都没有报告过页面焦点
- **THEN** 桌面应用提示无法确定目标浏览器，不执行插入

### Requirement: 写入文本与触发页面事件
收到插入请求时，扩展 MUST 重新校验目标字段仍存在、可编辑且可见，然后按插入模式写入文本：默认在光标处插入并替换当前选区，用户也可选择替换整个字段内容。写入后 MUST 触发页面可观察的 `input` 事件，并以冒泡方式触发 `change` 事件，使 React、Vue 等受控表单同步更新。

#### Scenario: 写入普通输入框

- **WHEN** 光标位于文本输入框末尾，扩展收到文本 `张三`
- **THEN** 字段内容变为原内容加 `张三`，并触发 `input` 与 `change` 事件

#### Scenario: 替换选区

- **WHEN** 输入框中有一段文本被选中，扩展收到插入文本
- **THEN** 选中文本被插入文本替换

#### Scenario: 替换整个字段模式

- **WHEN** 用户配置了替换模式，目标输入框已有内容
- **THEN** 字段原内容被解析结果完全替换

#### Scenario: 目标字段失效

- **WHEN** 插入前目标字段已被页面移除或变为只读
- **THEN** 扩展返回字段失效错误，不修改页面内容

### Requirement: iframe 与可编辑区域支持
扩展 MUST 支持跨域 iframe 中的可编辑字段，并把文本写入记录字段所在的 frame。对于 `contenteditable` 区域，扩展 SHALL 在光标位置插入文本并触发输入事件；不支持的可编辑区域 MUST 返回明确失败而不是破坏页面内容。

#### Scenario: iframe 内输入框

- **WHEN** 用户在跨域 iframe 的文本框中聚焦并提交命令
- **THEN** 文本写入该 iframe 内的输入框，而不是顶层页面

#### Scenario: contenteditable 区域

- **WHEN** 用户在 `contenteditable` 区域聚焦并提交命令
- **THEN** 文本插入光标位置，区域内容按页面编辑器预期更新

### Requirement: 插入失败反馈
扩展无法连接、当前标签页没有有效字段、字段失效或写入异常时，桌面应用 MUST 显示对应错误并保持浮层可用；不得把失败报告为成功，也不得静默丢弃解析结果。

#### Scenario: 扩展未连接

- **WHEN** 用户提交命令但扩展未连接
- **THEN** 桌面应用提示扩展未连接，浮层保持打开，浏览器字段不变

#### Scenario: 插入超时

- **WHEN** 桌面应用发出插入请求后未在限定时间内收到扩展结果
- **THEN** 桌面应用提示插入超时，不重复写入文本

### Requirement: 页面数据隐私
扩展 MUST NOT 读取、记录或向桌面应用发送页面内容、表单值或浏览历史；扩展只可在内存中保存当前焦点字段的定位信息，页面导航后清除。除回环地址上的本地连接外，扩展和桌面应用 MUST NOT 为该功能发起网络请求。

#### Scenario: 不上传表单内容

- **WHEN** 用户在多字段表单中聚焦某个字段并插入文本
- **THEN** 桌面应用只收到插入结果状态，不收到页面其他字段的值或页面内容

#### Scenario: 导航后清除焦点信息

- **WHEN** 活动页面发生导航
- **THEN** 扩展清除该标签页保存的焦点字段信息

### Requirement: 浏览器兼容范围
v1 扩展 SHALL 支持当前稳定版 Chrome 和 Edge 的 Manifest V3 扩展环境；其他浏览器不在本能力范围内。

#### Scenario: Chrome 与 Edge 加载扩展

- **WHEN** 用户在 Chrome 或 Edge 中以开发者模式加载扩展
- **THEN** 扩展可以连接桌面应用并完成文本插入
